REPEAT col IN ("price", "carat", "depth"):
  BRANCH WHEN TYPE(col) = NUMERIC THEN
    SELECT * FROM BIN_COUNT1D("diamonds", col, 20);
  ELSE
    SELECT * FROM VALUE_COUNT("diamonds", col);
  END
END

-- compiles to 3 SQL queries, one per column --

The Problem

Building a dashboard or an exploratory-analysis view almost always means writing the same SQL query over and over — once per column, once per facet, once per pairwise combination — with only a table or column name changing each time. Writing that by hand is tedious, and doing it programmatically means dropping into a general-purpose language and losing the readability of plain SQL.

CellQL: SQL, with Combinators

CellQL is a small orchestration language that sits directly on top of SQL. It adds four combinators — REPEAT, BRANCH, CONCAT, and QUANTIZE — for describing a family of related queries in one specification, plus data-analysis built-ins like BIN_COUNT1D and VALUE_COUNT. A CellQL program compiles directly to a list of plain SQL statements: nothing to execute at runtime, nothing beyond what a database already understands.

REPEAT

Loop a query template over a list of columns or values, generating one statement per iteration.

BRANCH

Pick a query shape based on a column's type — a histogram for numeric data, a count for categorical.

CONCAT

Run independent queries side by side as separate views in the same specification.

QUANTIZE

Split a query over data-driven buckets, such as deciles of a numeric column, computed from the data itself.
